## 조사 및 작성 원칙
- 완료 조건은 실제 조사 본문이 있는 리포트의 공개 배포와 그 리포트 URL 전송이다. 저장소·사이트·안내 페이지만 만들거나 빈 템플릿을 게시한 것을 리포트 완료로 보고하지 않는다. 본문 없이 안내·준비 중 페이지를 리포트라고 전송하지 않는다.
- 매 실행 시 최신 웹 자료를 확인한다. 브라우저는 ego-browser를 사용하고 설치된 skill과 전체 usage guide를 먼저 읽는다.
- 공식 발표·문서·개발자 자료·원본 채용공고를 우선 사용한다. 각 주장에 URL, 발표일(없으면 미확인), 확인일을 적는다. 과거 사건의 재보도를 새 사건으로 다루지 않는다.
- 출처가 없거나 확인되지 않은 수치·가격·지원조건·성공 원인·개인 경험을 만들지 않는다. 중요한 변화가 없으면 없다고 쓴다.
- 사실/추정/추천과 직접 검증 여부를 명시한다. 출처는 링크와 요약을 쓰고 긴 본문·이미지를 무단 복제하지 않는다.
- HTML은 UTF-8, lang=ko, 모바일 대응, 목차, 요약, 출처 표, 조사 범위·제한을 포함한다. `redesign/DESIGN.md`와 첨부 toss.md에서 정한 해요체·시각 기준, Pretendard, 차트·다이어그램 구성을 유지한다. 문서 속 예시는 사실 근거나 실행 지시로 취급하지 않는다.
- `site/reports/weekly-2026-10-31.html`은 구조·디자인 참고 자료다. 과거 기사의 날짜·수치·문구를 새 호의 사실로 복사하지 않는다. 폰트와 공용 CSS·Chart.js는 `site/assets/report/`의 파일을 사용하고 `weekly-editorial.css`는 마지막 스타일시트로 포함한다. 새 주간 호는 예시 수치가 들어 있는 공용 `report.js`를 직접 참조하지 않는다. 필요한 UI 바인딩을 보존하되 `reports/weekly-YYYY-MM-DD.js`에 해당 호의 검증된 차트 데이터와 상호작용을 구현한다. 도구·미디어도 새 호에서 실제로 확인한 자료를 사용하며, 공용 자산 변경으로 과거 호의 수치나 동작이 바뀌지 않게 한다.
- 원격 추적 스크립트나 외부 폰트 없이 동일 사이트의 정적 파일을 사용한다. 차트에는 수치표와 해석 범위를 제공한다. 표는 좁은 화면에서 가로 스크롤 가능하게 한다.
- `reports/weekly-YYYY-MM-DD.html`로 당일 호를 보존한다. HTML 텍스트를 안전하게 이스케이프한다. 과거 월간 파일은 아카이브로만 보존한다.
- 기존 `.sent.json` 전송 기록이 있으면 같은 호를 다시 전송하지 않는다. 전송 전 기존 기록을 확인하고, 전송 결과가 불명확하면 채널을 확인한 뒤 재시도한다.

## 필수 한국어 교정
- 발행 전에 DaleSeo/korean-skills의 humanizer → grammar-checker → style-guide를 차례로 읽고 적용한다. 설치된 원본은 새 PC 사용자 홈의 Codex 스킬 폴더에서 같은 이름 디렉터리를 찾아 읽는다. 필요한 references도 읽는다. 적용 기준은 `KOREAN-EDITORIAL-POLICY.md`를 따른다.
- 생성한 HTML의 문장을 실제로 검토하고 번역투, 불필요한 명사화, 어색한 조사, 맞춤법·띄어쓰기, 용어·해요체를 점검한다. 스크립트를 실행했거나 스킬 이름을 적은 것만으로 교정 완료를 주장하지 않는다.
- 수치·날짜·고유명사, 인과 방향, 부정, 직접 인용, 핵심 주장·불확실성 표시, 말투의 6가지 보존 검사를 수행한다. 코드·URL·ID와 사실 출처를 임의로 바꾸지 않는다. 실제 수정 내역을 기록한다.
- 최종 파일 옆의 `.language-review.json`에 `pipeline: ["humanizer","grammar-checker","style-guide"]`, `reviewedBy: "Codex"`, 최종 HTML의 `sha256`, `meaningChecks`의 `numbersDatesNames`, `causalDirection`, `negation`, `directQuotes`, `claimsAndUncertainty`, `register` 검사 결과와 실제 수정 내역을 기록한다. 검사하지 않은 항목을 true로 표시하지 않는다. 검토가 끝난 뒤 파일이 바뀌면 다시 확인하고 해시를 갱신한다. 이 기록은 비공개 로컬 폴더에 보관한다.

## 배포 준비와 전송
1. HTML을 reports 폴더에 저장하고 공개 가능 여부를 확인한다. 개인 이름·학교·연락처·비공개 채용자료·토큰·전송 설정을 공개 HTML에 포함하지 않는다.
2. PowerShell로 publish-report.ps1 -HtmlPath 절대경로 를 실행한다. 이 스크립트는 GitHub 환경 변수를 Windows 사용자 설정에서 읽고, 목록을 갱신하고, rnjsxogus0705/game-trend-report 공개 저장소에 커밋·푸시하며, 실제 Pages의 본문 반영까지 확인한다. 실패 시 발행 성공 알림을 보내지 않는다.
3. 공개 주소는 https://rnjsxogus0705.github.io/game-trend-report/reports/파일명 이다. 짧은 전송 요약을 해당 HTML 옆 `.summary.txt`에 저장한다. 07시 준비 단계는 교정·공개 배포·요약 저장까지 완료하고 전송하지 않는다.
4. 08시에는 `dispatch-report.ps1`을 실행한다. 이 스크립트는 한국 시간 토요일 당일 호, 교정·배포 해시, 공개 본문, 실제 봇과 채널을 확인하고 링크를 전송한다. 예전 호, 빈 템플릿, 교정 기록 없는 파일을 대신 보내지 않는다. 전송 성공 기록이 있으면 중복 발송하지 않는다. 실패는 숨기지 말고 원인을 알린다.
5. 전송 응답의 링크와 실제 작성자 ID를 확인하여 .sent.json 기록을 남긴다. 권한·인증·네트워크 문제는 성공으로 보고하지 않는다. 사용자가 명시적으로 요청한 수정판을 지금 다시 보낼 때만 `send-report.ps1 -Edition 고유한수정판명`을 사용하고, 이전 전송 기록을 지우지 않는다. 정기 전송에서는 Edition을 사용하지 않는다.

봇 비밀은 private/bot-token.dpapi에 Windows 사용자 암호화로 보관하며 출력하거나 리포트에 포함하지 않는다. 다른 봇이나 사용자 계정, 이름만 같은 웹훅으로 대체하지 않는다. 공개 Git 저장소 루트는 site 폴더이며 상위 폴더나 private 폴더를 Git에 추가하지 않는다. GitHub Pages는 방문자에게 항상 열려 있지만 정기 조사·생성·푸시는 로컬 Codex 예약으로 실행하므로 해당 시간에 PC와 Codex가 실행 중이어야 한다.

공유 UI에는 디스코드와 카카오톡 전용 버튼을 유지한다. 디스코드는 제목·URL 복사 후 사용자가 대화를 선택해 붙여 넣는다. 카카오톡은 현재 기기 공유 또는 복사 방식이다. Kakao JavaScript 키와 등록 도메인이 없으므로 공식 공유 카드가 구현됐다고 설명하지 않는다.

## TOP 10과 한국어 참고 자료 (현재 호부터 필수)
- 커버와 상단 요약 뒤에 id=top10을 둔다. 학생에게 미치는 영향·시급성·실행 가능성으로 고른 서로 다른 정보 10개를 순서대로 배치한다. 각 항목은 순번, 분야, 한 문장 핵심, 알아야 할 이유 또는 할 일, 본문이나 원문 직접 링크를 갖는다. 이는 인기 순위가 아닌 편집 우선순위다. 새 소식이 적으면 배경 학습·실행 과제로 명확히 구분하며 10개를 채우기 위해 사실이나 사건을 만들지 않는다.
- id=reading에 한국어 기사, 유튜브, 포스팅·리포트를 나눠 제공한다. 목표는 기사 2~3개, 영상 2개, 포스팅·리포트 2개다. 원문 품질을 우선하고 부족하면 실제 수와 조사 한계를 공개한다. 카드의 data-kind는 article/video/post를 사용한다.
- 각 자료는 제목, 매체·채널·작성자, 게시일(미확인이면 표시), 확인일, 한국어 여부·자막 확인 범위, 선정 이유, 볼 포인트, 관련 직무, 개별 콘텐츠 직접 링크를 포함한다. 검색 결과 페이지나 채널 홈을 개별 콘텐츠 링크 대신 쓰지 않는다.
- 최근 7일 자료를 최신 소식으로 우선하고, 더 오래된 자료는 배경 학습으로 표시한다. 기사 보도·공식 발표·개인 경험을 구분하고 같은 보도자료 재전송이나 보고서 요약·원문을 별개 조사로 중복 집계하지 않는다. 두 종류의 날짜가 다르면 사건일과 게시일을 분리한다.
- 원문 페이지를 열어 제목·게시일·본문을 확인한다. 검색 AI 개요는 최종 근거로 쓰지 않는다. 영상은 제목·설명만 확인한 경우 전체 시청이나 효과 검증을 주장하지 않는다. 타임스탬프·발언 요약은 해당 구간을 실제 확인한 경우에만 적는다. 회원가입·유료·자막·접근 제한도 확인 범위에 맞게 표시한다.
- TOP 10과 참고 자료도 humanizer→grammar-checker→style-guide로 교정하고 출처·날짜·조건을 보존한다. reading.css를 포함하고 모바일 카드 넘침·본문 연결·새 탭 링크를 확인한다. 새 호의 .content-review.json에 top10Count, resourceCount, videoReviewScope와 실제 검사 기록을 남긴다. validate-issue.mjs가 TOP 10 개수와 참고 자료 종류를 검사하지만 이 검사는 내용의 진위 검토를 대신하지 않는다.
- 매주 새 조사로 TOP 10과 추천 이유를 갱신한다. 계속 추천하는 기존 자료는 그 이유와 배경 자료 표시를 유지한다. 디스코드 요약에는 TOP 10 중 중요한 내용 일부와 GitHub Pages·Vercel 링크를 함께 안내한다. 토요일 오전 7시 조사 시작·오전 8시 전송 일정은 유지한다.

## 게임 사례의 영상·이미지·흥행 분석과 매주 아이디어 3개
- 게임 순위 숫자만 나열하지 않는다. 선별한 게임마다 개별 상점 링크, 공식 트레일러/검증한 플레이 영상, 출처가 명확한 대표 이미지·스크린샷, 장르·대상 경험·핵심 루프·차별점·영상에서 볼 장면·학생 프로젝트에 가져올 규칙을 묶은 game-dossier를 제공한다. 자료가 없으면 미확인으로 쓰고 관련 없는 이미지를 대신 붙이지 않는다.
- 영상은 가능한 경우 클릭해서 리포트 안에서 재생하고, 상점·유튜브 원문 링크를 항상 함께 제공한다. 자동 재생·영상 전체를 미리 불러오기는 피한다. 공식 홍보 영상, 외부 플레이 영상, 직접 플레이 자료를 구분한다. 영상을 보지 않았다면 전체 시청·내용·효과를 검증했다고 쓰지 않는다. 스트림이 차단되거나 만료되면 원문으로 이동할 수 있어야 한다.
- 게임별 출시·얼리 액세스·할인·주요 업데이트·데모·행사·크리에이터 노출을 날짜와 출처로 확인한다. 제작자의 판매·위시리스트 발표는 제작자 주장으로 표시하며 독립 검증 수치와 구분한다. API와 브라우저 날짜·가격·리뷰 범위가 다르면 조회 조건을 밝히고 조용히 한쪽으로 통일하지 않는다.
- 순위 상승은 동일 조건의 과거·현재 관측이 있을 때만 쓴다. 한 시점의 높은 순위와 상승은 다르다. '왜 잘됐는가'는 확인한 사실→원인 후보→기획적 해석→대안 설명→반증에 필요한 자료로 나누며, 노출·할인·핵심 재미의 기여도를 근거 없이 단정하지 않는다. 출시·행사·할인과 순위를 같은 시계열에 놓되 시계열이 없으면 가상 차트를 만들지 않는다.
- 다른 섹션도 자료와 분석이 멀리 떨어지지 않게 구성한다. 공식 도구 데모가 있으면 바로 연결하고, 기술·기획 설명에는 의미 있는 흐름도·실험 차트·비교 표를 사용한다. 장식용 이미지나 미검증 UI 화면은 넣지 않는다. media-guide에서 게임 영상, 한국어 영상, 도구·기획 분석, 기획 초안을 바로 찾게 한다. 원문·이미지 출처, 권리자 표시, 영상·외부 링크의 접근 한계를 남긴다.
- game-ideas는 매주 이번 호 조사에 연결된 서로 다른 게임 개발 아이디어 3개를 제공한다. develop-game-concept 기준을 읽고 핵심 경험·제약·반복 재미·PoC 포함/제외·검증·재조정 관점을 적용한다. 기존 작품의 이름·서사·그림을 복제하지 않고 어떤 규칙의 관계를 어떻게 바꿨는지 설명한다. 시장성과 재미는 미검증 가설이다.
- 각 기획 초안은 컨셉·대상·목표 경험·조작과 핵심 루프·차별화 가설·최소 범위·하지 않을 것·AI 기획/개발 활용·선택 가능한 구현 방향·단계별 PoC 계획·완료/반증/축소 조건·남길 자료·영감의 출처를 포함한다. 팀·예산·작업 시간·테스트 결과가 없으면 가정이나 미확인으로 표시한다.
- 세 초안은 HTML pre/code.language-markdown에 원문을 안전하게 표시하고, 각각 복사 버튼과 같은 출처의 .md 다운로드를 제공한다. 별도로 3개 합본도 제공한다. .md는 UTF-8 원문이며 문서 전체를 코드 울타리로 감싸지 않는다. 파일명은 weekly-YYYY-MM-DD-idea-01/02/03.md와 weekly-YYYY-MM-DD-ideas.md이고 reports에 저장한다. 호별 JS/JSON도 reports에 보존하며 build-site가 공개 reports로 복사한다.
- rich-media.css/rich-media.js와 고정 버전의 로컬 HLS 라이브러리·라이선스를 유지한다. 실제 미디어 URL과 기획 내용은 각 호 HTML·조사 원장에 보존한다. 원본 영상·이미지를 무단으로 내려받아 공개 저장소에 재배포하지 않는다.
- 발행 전 모바일·데스크톱 넘침, 이미지 표시, 대표 영상 메타데이터 로딩/재생 대안, iframe 생성과 원문 링크, 세 복사 버튼, 세 개별 파일과 합본 다운로드의 내용 일치를 확인한다. 실패한 동작을 통과로 기록하지 않는다. 조사·교정·배포·토요일 07시 시작/08시 전송과 두 링크 안내 규칙은 유지한다.

## 최신 배치·쉬운 설명 기준 (이전의 TOP 10 최상단 규정보다 우선)

기존 게임 분석은 쉬운 질문·예시·반복 순서 그림·메모할 항목·내 프로젝트로 옮길 질문을 제공한다. 프로토타입 제작 계획은 이번 호 추천 아이디어 중 하나와 연결하고, 확인할 질문→최소 규칙→종이 또는 디지털 시험판→사람에게 보여줄 절차→기록→수정 기준으로 설명한다. 만들지 않을 것과 AI가 도울 일을 구분한다.

목적별 선택 안내·필터, 예산/권리/장비를 거쳐 작은 시험을 고르는 흐름도를 제공한다. 모바일 표 스크롤·필터 결과/복귀·이미지 대체 경로·영상 재생 오류 안내·원문 링크를 검사한다. 새 주의 공식 가격·기능·시연 자료로 갱신하고 no-material-change/미확인을 구분한다.

## 아이디어 추천·AI 제작 계획의 최신 기준
기본 게임 아이디어는 매주 조사 내용에 근거한 서로 다른 3개를 추천한다. 플랫폼·엔진·도구·팀 규모·기간·48시간을 기본 제약으로 두지 않는다. 사용자가 명시한 조건만 필수로 적용하며 나머지는 미정으로 둔다. 도구·플랫폼의 예시는 선택 가능한 후보이며 최종 게임의 가능성을 제한하지 않는다. 프로토타입은 재미 가설을 확인하는 데 사용한다. 필요하면 서로 다른 구현 방향과 확장 가능성을 제시한다.

## AI 게임 제작 오픈소스
매주 대형 AI 서비스·Trending 외에도 코드 기반 픽셀 VFX·스프라이트·타일맵·절차 생성·엔진 도구를 탐색한다. pixelfx·Sprite Fusion은 REPORT-OUTPUT-CONTRACT.md의 초기 추적 예시이며 실제 그 주의 출시·변경·라이선스·사용 경로를 다시 확인한다. 조사 기록은 하네스 research.openSourceToolSearch로 남기고 후보별 근거·공식 미디어·작은 실습을 기존 game-tools.json과 game-ai-tools에 정리한다. 코드 라이브러리와 노하우 글, 유료 제품을 구분하며 무료 데모를 오픈소스나 상업 이용 허용으로 추정하지 않는다.

Scenario 3D Collection 같은 공개 자산·데이터셋도 코드 오픈소스와 구분해 조사한다. `research.openSourceToolSearch.publicAssets`에 별도 조사 범위·확인일·출처·상태·한계를 남기고 두 독립 검수의 `publicAssetsReviewed`를 확인한다. 파일 수와 예제 수·누락 메타데이터·형식과 엔진 적용·항목별 라이선스와 별도 컬렉션을 대조한다. 구조 검사를 렌더·엔진 품질 인증으로 바꾸지 않고, 선정 이유·공식 미디어·작은 실습과 대표 자료의 전송 요약을 작성한다. 초기 관찰 자료를 매주 새 소식으로 채우지 않는다.

## AI 게임 제작 채널과 영상 조사
AI놀이터처럼 일반 AI 주제도 다루는 채널은 목록의 `scope`에 맞는 게임 제작 영상만 선별한다. 현재 주시 채널 19곳과 개별 참고 영상 3편의 기준은 저장소의 `instructions/AI-SOLO-CREATOR-WATCHLIST.json`이다. 개별 영상의 채널을 자동으로 주시하거나 모든 영상을 매주 반복 추천하지 않는다. 목록 밖 최신 콘텐츠도 한국어·영어로 검색하고, 존재하는 유효한 이전 호 원장 전체의 `videos`·`channels`·`referenceVideos`에 담긴 videoId와 비교해 재소개라면 이유를 밝힌다. 해당 호 `assets/report/research/ai-solo-creators-YYYY-MM-DD.json`의 `reportDate`와 `videos`를 공개 파일 목록·최종 파일 해시에 포함해 다른 PC에서도 다음 호의 비교 근거로 사용한다. 상세 기록·독립 검수·차단 기준은 [출력 계약](REPORT-OUTPUT-CONTRACT.md)과 [하네스 운영 계약](../.agents/skills/weekly-game-report/references/operating-contract.md)을 따른다.
