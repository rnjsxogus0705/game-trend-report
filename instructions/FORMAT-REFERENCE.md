# 주간 리포트 형식 참조

새 호를 기획하기 전에 `.agents/skills/weekly-game-report/references/report-format-reference.json`의 기준 파일과 해시를 확인한다. 2026-10-31호와 2026-11-07호의 정보 구조, 카드, 목차와 읽기 동작을 참고한다. 이전 호의 사실, 숫자, 영상 또는 발행 상태를 새 자료로 복사하지 않는다.

표지와 `main.content`, 네 묶음 목차, 상단 요약, 순번과 본문을 구분한 TOP 10 및 필요한 카드·출처를 유지한다. 각 자료의 원문, 확인일, 게시일과 선정 이유를 확인한다. 미확인 값은 명시하고 자료가 없는 종류는 조사 범위와 한계를 남긴다. 영상과 그림은 출처·대체 텍스트·확인 범위를 구분한다. 각 아이디어와 AI 제작 계획은 개별 Markdown 전체를 접힌 `pre/code.language-markdown`에 담고 동일 내용을 복사할 수 있어야 한다.

작성자는 공통 HTML과 스타일, 스크립트의 기준 사본을 고정한다. 병렬 작성자는 승인된 패킷으로 자기 섹션의 후보 파일만 만들고 공통 파일을 수정하지 않는다. 조정자는 `workflows/assemble-report-sections.mjs`로 공통 셸, 스타일·스크립트 해시, 패킷과 섹션 해시, DOM ID를 검증한 다음 단일 결과를 조립한다. 필요한 섹션이 없거나 충돌·변조가 있으면 중단하고 다시 작성한다. 실제 의미·한국어·원문 및 독립 화면 검수는 이 기계 검사를 통과했다고 면제되지 않는다.

320·390·768·1440px의 실제 화면에서 이전 호와 같은 폭의 카드, 펼친 상세, 필터의 select·button 계산 스타일과 조작, 문장 줄바꿈, 최소 글자 크기, 포커스, 복사, 접기, 미디어 표시·영상 대체 링크와 인쇄를 확인한다. 원문 링크만 나열했는지와 실제 표시된 미디어를 구분한다. [미디어 계획과 실제 화면 검수](QUALITY-PIPELINE.md#미디어-계획과-실제-화면-검수)의 섹션별 조사·배치·이유를 SQLite 및 검수 증거와 대조한다. 미디어 또는 자료를 구하지 못하면 부적절한 자료로 수량을 채우지 않고 확인한 범위와 사유를 기록한다.

`gitRevision`이 있는 기준은 working tree가 아니라 `git show <gitRevision>:<path>`의 실제 바이트로 SHA256을 확인한다. 기준별 capabilities가 지원 범위를 표시한다. Oct31은 개별 Markdown 전체 복사 기준이고, 고정 Nov7 a9e84e4는 셸·목차 참고이며 전체 원문 복사가 구현된 예시가 아니다. JSON의 targetContract는 새 결과의 필수 조건이다. 날짜는 가능한 `.cover-meta time[datetime]`을 쓰고, 과거 `.issue-cover > p` 대안은 실제 날짜 텍스트와 발행일을 대조한다.

공통 셸과 상태 목록은 `references/report-format-reference.json`의 `coreUi`와 루트 `DESIGN.md`를 따른다. 가장 최근 실제 검수본의 컴포넌트 형식을 우선하고, 고정된 부실 과거본을 폼·미디어 완성 예시로 복제하지 않는다. 공유 버튼은 정적 셸에도 포함하고 긴 본문 중간에서도 찾을 수 있어야 한다. 새 디자인 기준은 UI 증거의 `designContractSha256`으로 결속하며 존재하는 버튼과 실제 동작을 각각 확인한다.

다음 호의 우선 고정 예시는 `07ce6c8b24915256a9cfb70544d3a8ffd3bc118c`의 2026-11-07호다. JSON의 해당 SHA256과 git 객체를 대조하고 개선된 카드·공유·미디어·전체 Markdown 복사·검색·범위별 상세 제어·독자용 문장 구조를 참고한다. 이전 a9e84e4는 실패 비교용으로만 둔다. 공통 디자인·셀렉터·동작을 착수 전에 고정해 제작 막바지의 전역 수정과 전체 UI 재검수를 줄인다. 고정본의 해당 호 JS까지 함께 확인한다. HTML 예시만 복사하면 영상 재생 핸들러가 빠질 수 있다.


## 본문 검색과 공통 탐색

데스크톱에서는 좌측 목차에, 모바일에서는 상단 목차 또는 헤더에 본문 검색을 배치한다. 두 검색 인터페이스는 검색어·결과 수·현재 결과를 공유하며 고유 패널 ID와 명확한 접근성 이름을 갖는다. 결과의 이전·다음 이동, Enter/Shift+Enter, Escape로 닫기와 포커스 복귀, 결과 없음과 빈 검색어, 접힌 상세의 결과 자동 열기를 제공한다. 검색 결과는 원문과 링크의 텍스트·동작을 바꾸지 않고 이동할 수 있어야 한다. 템플릿의 검색 마크업은 작성 예시이며 공통 스크립트의 실제 적용과 화면 동작을 대신하지 않는다.

독립 UI 검수자는 320·390·768·1440px에서 실제 검색과 양쪽 상태 동기화, 한글·특수문자·여러 결과·0건·닫힌 상세·반복 검색, 키보드 포커스와 공유·영상·인쇄 간섭 여부를 확인한다. 검색 결과와 독자 본문의 무결성을 검토하고 이미지 속 문자나 외부 iframe 내용이 검색 범위에 포함되는지 임의로 보장하지 않는다. 검색 공통 셸·CSS·JS가 바뀌면 영향받는 UI를 다시 검수하고 파일 해시를 실행 증거와 결속한다.

목차 검색은 좁은 좌측 영역에서 한눈에 읽히도록 간결하게 배치하고 결과가 없을 때 불필요한 이전·다음 조작을 숨긴다. 접근 가능한 이름과 최소 44px 조작 영역은 유지한다. 레이아웃 전환점이 바뀌면 전환점 양쪽 폭도 추가 확인한다.

## 도구 상세 펼침·접기

도구 상세를 일괄 펼치고 접는 조작은 적용 대상 도구 목록 바로 앞에 배치하고, 버튼 이름이나 인접 설명에 대상 범위를 명시한다. 독자가 화면의 다른 섹션이나 목차까지 조작된다고 오해하지 않도록 표시한 대상만 변경한다. 개별 상세의 기본 조작과 키보드 포커스를 유지한다.

독립 UI 검수자는 네 화면 폭에서 버튼과 대상의 위치 관계, 명확한 범위 표현, 전체 펼침·접기와 다른 섹션의 불변 상태를 실제 확인한다. 공통 검색 및 인쇄와의 상호작용도 변경 범위에 포함해 확인한다.

## 선택적 부가정보 상세

상단 요약과 TOP 10, 게임 제작 도구, 픽셀 효과·공개 자산처럼 한 섹션에 근거와 조건이 많은 경우에도 핵심 판단·선정 이유·독자가 할 일은 기본 화면에 둔다. 선택적으로 확인할 근거·자산·도구 설명만 `details.reading-detail[data-detail-kind]`에 넣고 `evidence`, `asset`, `tool` 중 실제 역할을 표시한다. `summary`는 “자세히 보기”처럼 모호하게 쓰지 않고 펼쳤을 때 읽을 내용을 짧게 밝힌다.

본문은 `.detail-body`, 확인일·출처·라이선스·미확인 한계는 `.detail-meta`에 둔다. 접힘은 정보를 삭제하거나 필수 조건을 감추는 수단이 아니며 텍스트는 검색·복사·보조 기술과 인쇄에서 계속 접근할 수 있어야 한다. 같은 도입이나 조사 과정 문구를 펼침 안팎에 반복하지 않는다. 독립 UI 검수자는 320·390·768·1440px의 라이트·다크에서 열린/닫힌 상태, 긴 링크·미디어·포커스·검색 자동 펼침과 인쇄를 확인한다.

## 공통 탐색 자산과 로드 순서

새 호는 기존 공통 CSS 뒤에 `assets/report/section-infographic.css`, `assets/report/report-theme.css`, `assets/report/report-search.css`를 이 순서로 연결한다. `assets/report/report-theme.js`는 첫 화면 전에 설정을 적용하도록 `head`에서 동기 실행한다. `defer` 스크립트는 `assets/report/share-v2.js` → `assets/report/reading-experience-scoped-v2.js` → `assets/report/report-search.js` → 해당 호 `reports/weekly-YYYY-MM-DD.js` 순서로 배치한다. 검색 스크립트는 생성된 펼침 요소를 포함한 본문을 대상으로 동작해야 한다. 기존 공개호의 `share.js`·`reading-experience-scoped.js`를 덮어쓰거나 새 버전과 같은 페이지에 함께 연결하지 않는다.

예전 호의 펼침과 검색 동작이 바뀌지 않도록 이미 참조 중인 `reading-experience.js`는 수정하지 않는다. 신규 파일과 검색 CSS·JS를 해당 호의 공개 파일 원장, 공통 presentation 해시, 실제 UI 검수에 포함한다. 예전 호는 발행 당시 연결된 파일을 그대로 사용한다.

## 섹션별 구조화 템플릿과 SQLite 캐시

원본은 `.agents/skills/weekly-game-report/references/section-templates.json`이다. 22개 섹션의 그룹·작업 범위·중첩 소유·필수 원고·미디어·실습·검수 기준과 빈 컴포넌트를 제공한다. 두 호의 실제 참조 해시를 대조하고, 공통 디자인과 스타일은 실행 당시 해시로 고정한다. 템플릿 예시의 플레이스홀더는 작성 설명이며 공개 결과물이 아니다. 이전 본문의 사실·영상·그림·날짜를 새 호에 자동 복사하지 않는다.

```sh
python3 workflows/report-template-store.py import
python3 workflows/report-template-store.py check
python3 workflows/report-template-store.py list
python3 workflows/report-template-store.py section --id reading
python3 workflows/report-template-store.py section --id reading --run 실제-run-id
```

시작 시 import/check를 한 번 수행하고 실제 카탈로그 경로·SHA256을 context에 기록한다. Git의 카탈로그가 단일 원본이고 SQLite `template_versions`/`template_sections`는 hash별 불변 조회 캐시다. 원문·기존 연구·승인 이력을 템플릿마다 복제하지 않는다. 변경되면 새 버전으로 적재하고 기존 버전은 보존한다. 다른 PC에서는 카탈로그로 캐시를 재구축할 수 있다.

조사 담당에는 해당 섹션의 fields·media·practice, 작성 담당에는 해당 템플릿과 원장의 승인 패킷만 전달한다. `section --run`은 기존 packet 게이트를 직접 호출하므로 stale/미승인 자료를 승인으로 우회하지 못한다. 템플릿 전용 조회는 승인과 독립 검수가 아니다. `game-ai-tools`와 하위 `agent-skills`는 같은 작업 범위를 유지한다. 공유 shell·CSS·JS는 감독자 단일 소유, 섹션 fragment만 병렬 작성한다.

읽을거리·게임의 영상은 링크 목록만으로 미디어 배치 완료로 표시하지 않는다. 해당 호의 선정 자료에 맞는 이미지·미리보기·플레이어를 배치하고 임베드 불가·권리·접근 문제는 원장에 남긴다. 두 호의 수량 차이는 검수 후보이며 최소 수량을 억지로 채우는 기준이 아니다. 생성 그림은 의미가 있는 곳에 실제 생성·출처·한국어 검수를 거쳐 추가한다. 공유·읽기·복사·다운로드·필터·인쇄와 4폭 화면 검수는 기존 coreUi 계약대로 유지한다.

## 섹션별 한글 요약과 인포그래픽

각 섹션은 제목 가까이에 그림과 한국어 요약을 한 묶음으로 배치한다. 요약 제목과 핵심 2~3개는 이미지에만 넣지 않고 실제 HTML 문장으로 작성해 복사·검색·보조 기술 이용이 가능하도록 한다. 2026-11-07의 별도 미승인 시안에서 확인한 구조를 빈 컴포넌트로 정리한 것이며, 시안의 원고·이미지 또는 승인 상태를 새 호로 복제하지 않는다. 생성 그림은 개념 그림임을 명시하고 실제 도구 화면·측정치·실험 결과처럼 표현하지 않는다. 이미지·요약이 해당 섹션 전체를 대표하는지 확인하고 중첩 섹션은 별도 고유 ID를 쓴다.

요약은 해당 호의 근거와 승인된 본문을 바탕으로 작성하고 이미지의 파일·해시·출처·권리·생성 근거와 검수 결과를 미디어 원장에 연결한다. 자료가 부족하면 사실을 만들거나 무관한 그림으로 채우지 말고 사유를 기록한다. `section-templates.json`의 `sectionInfographic` 예시와 `sectionVisualContract`는 형식 가이드이며 이미지·한국어·원문 승인과 실제 렌더러 연결을 대체하지 않는다. 공통 `assets/report/section-infographic.css`의 실제 해시를 고정하고 독립 검수자가 320·390·768·1440px에서 배치, 읽기, 종횡비, 이미지와 대체 텍스트, 공유·검색 간섭을 확인한다.

## 핵심 먼저 보기와 부가 상세

`#issue-summary`, `#top10`, `#game-ai-tools`, 그리고 그 안의 ‘코드로 만드는 픽셀 효과와 공개 3D 자산’ `.media-resource`는 제목과 핵심 판단, 선정 이유, 독자가 바로 할 일을 펼침 없이 먼저 보여 준다. 마지막 대상은 `game-ai-tools` 안의 항목으로 유지하며 임의로 새 최상위 섹션으로 분리하지 않는다. 같은 결론을 여러 카드와 캡션에서 반복하지 않고 상단 네 영역의 제목·요약·행동 위계를 간결하게 맞춘다.

조사 경위, 부가 배경, 전체 조건표와 긴 원문 설명은 관련 핵심 바로 뒤의 기본 닫힌 `details.reading-detail`에 둔다. `summary`는 ‘자세히 보기’처럼 모호하게 쓰지 말고 펼쳤을 때 나오는 날짜·조건·근거의 범위를 한국어로 알려 준다. 날짜·마감·학년도나 기수·자격·비용과 장학·라이선스 예외·확인일·출처·미확인 한계는 삭제하거나 의미를 축약하지 않는다. 지원·사용 판단을 뒤집는 상태나 예외는 펼침 밖에도 짧게 알리고, 전체 값은 `detail-meta`를 포함한 상세에서 검색·복사·보조 기술·인쇄로 정확히 확인할 수 있게 한다.

개념 이미지 캡션은 출처 또는 AI 생성임을 밝히고 실제 제품 화면·측정·실행 결과가 아니라는 점을 짧게 표시한다. 조사 과정을 장황하게 반복하거나 본문 요약을 캡션에 다시 쓰지 않는다. 독립 검수자는 320·390·768·1440px에서 네 영역의 펼침 전 위계, 상세의 인접 위치와 기본 닫힘, 키보드 이름, 검색 결과의 자동 열림, 공유·인쇄, 라이트·다크 대비를 확인한다.

### TOP 10과 도구 카드의 기본 미디어

TOP 10 항목과 `#game-ai-tools`의 개별 도구 카드·내부 제작 자료는 관련 공식 영상, 제품 화면 또는 공식 저장소 이미지가 있고 표시 출처와 사용 조건을 확인했다면 제목과 핵심 설명 바로 가까이에 썸네일이나 클릭형 미리보기로 보여 준다. 이 미디어는 `details.reading-detail` 밖에 두어 상세를 펼치지 않아도 어떤 자료인지 판단할 수 있게 한다. 영상은 검증된 썸네일·제목·원문 대체 링크를 유지하고 실제 플레이어나 외부 자원 로딩은 명시적인 사용자 동작 뒤에 시작한다.

표시할 관련 미디어가 없거나 직접 표시·재사용 조건을 확인하지 못했다면 무관한 이미지나 생성 그림으로 자리를 채우지 않는다. 기본 화면에 미디어를 쓰지 않은 이유와 공식 원문 또는 영상 링크를 제공한다. 공식 원문·미디어 제목·짧은 출처와 사실 오인 방지 문구는 보이는 영역에 남기고, 조사 경위와 긴 라이선스 조건·전체 확인 범위만 인접한 기본 닫힌 상세로 옮긴다. 날짜·비용·라이선스 예외가 사용 판단을 바꾸면 그 조건도 핵심 설명에서 짧게 알린다.

독립 검수자는 카드별 공식성·항목 관련성·표시 조건·로컬 파일 해시·대체 텍스트·실제 로딩과 영상 대체 링크를 원장과 대조한다. 320·390·768·1440px의 기본 닫힘 화면에서 미디어가 해당 제목과 인접하고 잘리지 않는지, 검색·공유·인쇄·라이트/다크 테마와 충돌하지 않는지 확인한다.

## 테마와 중첩 요소

헤더 테마 버튼은 시스템·라이트·다크를 순환하고 현재 설정을 한국어와 접근성 이름으로 표시한다. 저장된 설정과 시스템 테마 변경, 저장소 접근이 불가능한 경우, 인쇄 시 라이트 표시를 확인한다. 장식용 인라인 아이콘은 보조 기술에서 숨기고 버튼에 별도 접근성 이름을 둔다. 펼침 영역 안의 안내 상자는 배경과 테두리로 바깥 영역과 구분하며 라이트·다크 각각의 텍스트와 제어 대비를 검수한다. 네 화면 폭에서 키보드 조작, 공유·검색 및 인쇄와의 간섭을 독립 확인한다.
