# 읽기 경험과 예약 작업 재현 지침

이 문서는 `REPORT-GUIDE.md`, `REPORT-OUTPUT-CONTRACT.md`, `WORKFLOW.md`와 함께 매 실행 전에 읽는다. 기존의 필수 섹션, 실제 조사, 교정·검수·배포 및 중복 전송 방지 조건은 그대로 적용한다. 현재는 매주 발행하며 월간 단독 발행은 하지 않는다.

## 메인과 누적 아카이브

- 첫 화면의 주 동작은 발행된 `weekly-YYYY-MM-DD.html` 중 날짜가 가장 최근인 **주간** 호를 연다. 월간은 과거 아카이브로 분리한다. 주간이 없으면 발행 안내를 표시한다. 파일명을 신뢰할 수 있는 형식으로 검사하고 제목은 HTML로 이스케이프한다.
- 주간·월간 자료는 최신순으로 정렬하고, 개수가 늘어도 월별로 찾을 수 있게 묶는다. 제목·날짜 검색, 유형과 연도 선택을 제공하며 검색은 전체 목록에 적용한다. 현재 선택 조건, 결과 수와 결과 없음 상태를 읽을 수 있어야 한다.
- 가장 최근 월은 처음부터 보여 주고 이전 월은 접는다. 각 묶음의 제목에 연월과 건수를 적는다. 스크립트를 사용할 수 없어도 목록의 모든 링크를 펼쳐 접근할 수 있어야 한다. 단순한 목록을 불필요하게 여러 페이지로 쪼개지 않는다.
- 새 호 발행 시 사이트 생성기가 최신 주간 연결과 목록을 다시 만든다. 생성된 index.html만 수정하지 말고 `workflows/build-site.mjs`의 생성 원본도 함께 반영한다. 검색·필터 초기화, 월 경계와 주간 파일이 없는 경우를 검사한다.

## 본문과 목차의 네 범주 (2026-11-07부터 최우선)

아래 순서는 이전의 단일 목차 및 섹션 간 배치 규정보다 우선한다. 기존의 필수 내용·출처·사실과 앵커 ID는 유지한다. 커버는 맨 앞, 푸터는 맨 끝에 둔다. 본문은 네 개의 `.report-part` 요소에 `data-report-part` 값을 붙여 순서대로 묶는다. 왼쪽 목차도 같은 순서의 `details.toc-group[data-toc-group]` 네 개로 구성한다.

| 값과 범주 | 본문 순서와 포함할 내용 |
|---|---|
| `overview` 핵심 요약 | `issue-summary` → `top10`. 기존 `brief`와 안내문은 `issue-about` 접힌 개요에 보존 |
| `tools` AI 도구와 기술 | `game-ai-tools`(하위 `agent-skills`) → `github-trending` → `ai-trends` → `game-ai` → `ai-releases` → `techniques` |
| `making` 게임 분석과 제작 | `games` → `reverse` → `ai-only-lab` → `ai-planning` → `game-ideas` → `ai-production` → `prototype` → `lab` |
| `resources` 취업과 참고 자료 | `careers` → `opportunities` → `reading`(하위 `media-guide`) → `sources` |

범주에는 명확한 `.part-heading` 구분 막대를 두고 각 장 사이에는 아래의 구분선 기준을 적용한다. 왼쪽 목차의 네 `details`는 `name="report-toc"`을 공유해 한 범주씩 열며 기본은 `overview`다. 현재 위치의 범주를 자동으로 열고 현재 항목을 표시한다. 모바일 접는 목차에도 네 범주명과 동일한 링크 순서를 제공하고 `agent-skills`는 하위 들여쓰기로 구분한다. 기존 요약의 중복 목차 링크는 정리하되 `brief` 내용과 안내문은 삭제하지 않는다. 상단 핵심 판단·도구 선택·이번 주 할 일 세 줄은 매주 해당 호의 실제 새 조사에 근거해 다시 작성한다.

2026-11-07 이후 호는 `validate-issue.mjs`의 범주 순서 검사를 통과해야 하며, 실제 사실과 원문 보존 여부도 별도로 확인한다. 범주 이동 자체를 문장 삭제로 취급하지 않는다.

## 긴 리포트의 구성과 접근성

- 목차, TOP 10 중 우선 읽을 처음 3개, 핵심 발견과 선택에 필요한 요약·가격 조건은 바로 볼 수 있게 둔다. TOP 10의 나머지 7개는 순서와 출처를 유지하며 선택해 펼칠 수 있게 한다. 상세 설명·긴 출처 목록 등 보조 자료만 제목이 구체적인 `details`/`summary`로 접는다. 독자가 핵심 내용을 읽으려고 모든 항목을 열어야 하는 구성은 피한다.
- 가능하면 상세 전체 펼치기·접기를 제공한다. 본문 앵커로 이동하면 대상의 접힌 상위 항목이 열려야 하고, 키보드와 스크린 리더에서 상태와 조작이 이해되어야 한다. 인쇄·PDF에는 접힌 정보도 포함한다. JS 실패 시에도 기본 내용을 읽고 상세를 열 수 있도록 한다.
- 모바일 320px 이상과 데스크톱에서 목차 이동, 키보드 초점, 펼침 상태, 표의 가로 스크롤, 이미지 대체 텍스트, 인쇄, 공유·복사·다운로드·영상 재생을 실제로 검사한다. 새 UI가 기존 도구 필터나 과거 호의 기능을 바꾸지 않도록 확인한다.

## 주간 편집형 화면의 출력 규칙

- 새 주간 호의 `body`에 `weekly-editorial` 클래스를 적용하고 `../assets/report/weekly-editorial.css`를 해당 HTML의 **마지막 스타일시트**로 포함한다. 이 스타일은 주간 화면에만 적용하며 이전 월간 호를 바꾸지 않는다. 자산이 없거나 로드할 수 없으면 발행을 중단하고 경로를 바로잡는다.
- 커버에 이 호의 고유 제목인 유일한 `h1`을 둔다. 커버 바로 다음과 TOP 10 앞에 `.issue-summary#issue-summary`를 배치하고 목차 첫 링크로 연결한다. `h2`는 ‘이번 호 한눈에 보기’이며 해당 호의 실제 내용에서 다시 작성한 핵심 판단·도구 선택·이번 주 할 일 세 가지와 도구·게임·아이디어·취업·기회 바로가기 링크를 담는다. 확인되지 않은 기능·성능 순위를 만들지 않는다. `#top10`의 제목은 `h2`, 각 항목은 적절한 하위 제목으로 작성한다. TOP 10을 평면 목록으로 구성해 처음 3개를 먼저 보여주고 나머지 7개도 펼쳐 읽을 수 있게 한다. 정보·링크·출처를 줄이거나 순번을 바꾸지 않는다.
- `redesign/DESIGN.md`의 색상·Pretendard·18px/1.85 본문·최대 72ch 문단·제목/캡션 크기와 여백을 따른다. 큰 장 위에 2px `#AEBCCD` 구분선을 두고 위쪽 간격 64px(모바일 48px)을 확보한다. 장 제목 아래에는 1px 보조선을 두고 `h2`를 먼저, `.chapter-index` 메타데이터를 그 아래에 둔다. 데스크톱 목차의 독립 스크롤과 현재 항목 표시, 모바일 고정 접기 목차, 모든 섹션의 일관된 펼침 표시를 제공한다.
- 핵심 판단과 실행은 `mark` 배경 `#E2EBFF`, 글자 `#193E96`으로 필요한 곳에만 강조한다. 주의 조건은 `mark.caution`의 배경 `#FFF0CA`, 글자 `#704708`, 점선 밑줄을 사용한다. 색만으로 뜻을 전달하지 않으며 강조 과정에서 문구·부정·불확실성을 없애지 않는다. 한 장에서 남발하지 않는다.
- 조작 아이콘은 고정된 로컬 Lucide SVG 스프라이트(`assets/report/icons/lucide.svg`, ISC)와 공용 `share.js`를 재사용한다. 공유·복사·다운로드·인쇄·닫기 등 모든 버튼에 텍스트 또는 접근 가능한 이름을 둔다. 공유 메뉴의 `share-mark.png`는 image_gen 장식 이미지다. 설명에 새 삽화가 필요하면 image_gen을 사용하되, 실제 도구 화면은 공식 원본을 우선하고 차트·수치는 검증된 데이터와 코드/SVG로만 만든다. 생성 이미지의 출처와 프롬프트는 `assets/report/icons/SOURCES.md` 등 해당 자산의 출처 문서에 기록한다.
- 상세 접기·앵커 이동·인쇄, 목적 필터와 비교, 공유·복사·미디어·그래프 기능을 연결하고 호별 데이터와 ID를 확인한다. 현재 공용 `tool-choice.js`는 성능 직접 비교를 하지 않았다는 문구와 비교표의 세 번째 가격 열·여섯 번째 출처 열을 전제로 한다. `reading-experience.js`의 미리보기는 `tool-spritegen`, `tool-meshy`, `tool-runway` 세 ID를 찾는다. 새 호의 실제 실험 범위, 표 또는 후보가 다르면 과거 호의 공용 파일을 덮어쓰지 말고 호 전용 JS를 작성하며 공식 미디어와 해당 호 조사 원장도 함께 갱신한다. 미리보기·차트의 문구와 데이터가 새 조사 결과와 일치하는지 확인한다.
- 320·390·768·1440px에서 커버, 제목 계층, 본문 폭과 색 대비, 목차 독립 스크롤과 현재 위치, 모바일 목차, 첫 3개 및 나머지 항목, 표·차트·영상, 상세 펼치기와 해시 이동, 키보드 조작, 인쇄의 내용 보존을 확인한다. JavaScript 미지원 시에도 필수 본문과 수동으로 열 수 있는 상세가 접근 가능해야 한다.

## TOP 10의 선정 근거와 실행

- TOP 10은 인기·매출·성능의 실측 순위가 아니라 편집 우선순위다. 매주 원문을 직접 확인하고 각 항목에 선정 이유, 학생에게 미치는 영향, 지금 할 수 있는 행동 한 가지를 구체적으로 적는다. 근거가 부족하면 그 한계와 미확인 상태를 드러내고 순위를 사실인 것처럼 꾸미지 않는다.
- 각 항목에 읽을 수 있는 출처명과 자료 유형(공식 발표·논문·기사·기존 배경 등), 사건/게시일 또는 미확인, 확인일, 검증 범위와 한계를 표시하고 원문 또는 해당 본문으로 연결한다. 확인된 사실과 분석·제안을 구분하고 핵심 문구를 적절히 강조한다. 날짜만 바꾸거나 지난 호의 선정 이유를 새 조사 결과처럼 재사용하지 않는다.

## 장별 그림과 미디어

- 각 내용 장은 핵심 판단·제작 과정·게임의 선택처럼 독자가 빠르게 이해할 개념을 고르고 image_gen으로 그 장에 맞는 요약 그림을 만든다. 그림 옆에 간단한 텍스트 요약과 캡션을 함께 제공한다. 같은 설명을 반복하는 빈 장식이나 불필요한 아이콘은 추가하지 않는다. 생성이 불가능하거나 결과가 부정확하면 그 사실과 누락된 범위를 검수 기록에 남기고 생성했다고 쓰지 않는다.
- 생성 그림은 개념 설명이다. 실제 제품 화면, 게임의 출시 증거, 실제 시험 결과나 검증된 수치처럼 제시하지 않는다. 도구·게임의 실제 화면은 이용 조건을 확인한 공식 자료를 우선하고, 수치·차트는 확인된 데이터와 코드/SVG로 만든다. 생성 그림마다 파일명·프롬프트·생성 도구·용도와 실제 화면이 아니라는 구분을 해당 자산의 출처 원장에 기록한다.
- 이미지의 대체 텍스트는 핵심 내용을 전달하고, 그림 속 작은 한글 문구의 정확성과 모바일에서의 가독성을 확인한다. 글자가 깨지거나 내용이 틀리면 다시 생성하거나 정확한 HTML 텍스트로 설명한다. 색·그림에만 필수 의미를 맡기지 않는다.
- 공식 사진이나 영상이 있는 장은 관련성이 높고 확인된 대표 자료 1~2개를 접힌 상세 밖에서 먼저 볼 수 있게 둔다. 나머지 자료와 긴 설명은 선택적으로 펼친다. 공식 자료의 출처·확인일·확인한 범위를 남기고 접근 제한을 표시한다.
- YouTube는 클릭한 뒤에만 `youtube-nocookie.com`으로 재생하고 자동 재생하지 않는다. 재생할 수 없는 경우에도 해당 영상의 원문 링크를 제공한다. 영상 제목·설명만 확인한 경우 전체 시청이나 실험 재현을 주장하지 않는다. 조작 아이콘은 기존 Lucide 자산과 읽을 수 있는 버튼 이름을 사용한다.

## Agent Skill 선정과 근거

- 각 후보가 어떤 게임 제작 작업에 연결되는지와 선택 이유, 문서에서 확인한 강점, 도입 부담·제약, Codex 등 호환성의 근거, 학생이 해볼 작은 시험을 구체적으로 설명한다. 공식·커뮤니티·이번에 새로 관찰한 후보를 구분하고 단일 스킬, 여러 스킬을 고르는 라우터, 외부 도구 연결형을 구분한다. 별 수나 인지도만으로 추천하지 않는다.
- README, 실제 SKILL.md와 릴리스·관련 변경 원문을 확인하고 링크한다. 문서에서 확인한 내용과 직접 설치·실행·재현한 범위를 분리한다. 기존 관측 스냅샷은 그대로 보존하고 새 확인은 새 호의 관측 시각과 원장에 기록한다. 확인하지 못한 기능·호환성·비용·권리는 미확인으로 둔다.
- 제작된 게임 사례나 성과는 원문 근거가 있는 경우에만 링크하고 제작자 시연, 공식 출시, 독립 재현을 구분한다. 확인된 사례가 없으면 실적 미확인이라고 쓴다. 관련 영상·그림은 각 후보 설명 가까이에 대표 자료를 배치하고 자료가 없다면 일관된 기능 아이콘을 사용한다. 브랜드 로고를 임의로 만들지 않는다.
- 작업 범주 매트릭스와 제작 단계 연결도로 정성적인 차이를 보여 준다. 비교에는 확인한 조건과 한계를 표시하고 같은 조건의 독립 실측이 없는 성능 점수나 순위를 만들지 않는다. 핵심 판단은 필요한 곳에 강조하되 사실·제약·불확실성을 삭제하지 않는다.

## 이해할 수 있는 설명과 해외 제작 자료

- 각 섹션의 도입에서 무엇을 다루는지, 왜 학생에게 필요한지, 무엇을 직접 해볼 수 있는지 구체적인 예와 함께 설명한다. 처음 나오는 전문 용어는 쉬운 풀이를 붙인다. 명사가 길게 이어지는 문장과 같은 말을 되풀이하는 얕은 요약은 실제 행동과 결과가 보이도록 고친다.
- 한 가지 공통 예시를 골라 기획 → 자산 → 코드 → 플레이테스트가 어떻게 이어지는지 설명한다. 예시는 학습을 돕기 위한 편집 제안과 실제로 제작·시험한 결과를 구분한다. 하지 않은 제작이나 테스트를 수행했다고 쓰지 않는다.
- 다이어그램은 각 단계의 입력·행동·출력과 필요한 분기·판단을 드러내고 본문에서도 읽을 수 있게 설명한다. 신뢰할 수 있는 실측이 없으면 그래프 수치를 만들지 않으며 검증 범위를 밝힌 비교표·흐름도를 우선한다. image_gen 이미지의 한글 문구, 캡션, 대체 텍스트와 본문이 같은 내용을 전달하는지 확인한다.
- 한국어 자료에 한정하지 않고 AI 제작, 게임 디자인, 코딩 실습, 엔진 실무로 나누어 해외 자료도 매주 조사한다. GDC, Game Maker’s Toolkit, Sebastian Lague, 공식 엔진 채널 등을 후보로 삼되 채널명만으로 선정하지 않는다. 공식 원문에서 제작자·행사 성격·제작 내용을 확인하고 학생이 배울 구체적 이유를 적는다. 확인하지 못한 유명성·조회수·성과를 추정하지 않는다.
- 과거의 좋은 자료는 게시 시점을 밝혀 배경 학습으로 제공하고 이번 주 신규 소식으로 표시하지 않는다. 개별 영상·글의 직접 URL, 제목, 제작자, 게시일 또는 미확인, 원어, 확인한 자막 유무, 볼 때 생각할 질문, 자료가 실제로 설명하는 범위, 직접 시청 여부를 기록한다. 제목과 설명만 확인했으면 전체 영상을 시청했다고 쓰지 않는다. 한국어 독자가 어디부터 볼지와 어려운 용어를 짧게 안내하며 자막·번역의 품질을 확인하지 못했으면 미확인이라고 쓴다.

## 도구 선택 결과와 제작 경로

- 독자가 목적을 고르면 무엇이 달라지는지 먼저 설명한다. 조작 바로 옆에 현재 선택과 일치하는 후보 수를 표시하고, 바로 아래에 실제로 바뀌는 후보 목록을 둔다. 각 후보는 확인된 공식 제품·결과 이미지 썸네일, 이름, 해당 도구의 상세 설명으로 이동하는 링크를 제공한다. 원본 이미지가 없거나 이용 조건을 확인하지 못했다면 출처와 함께 미확인 상태를 표시한다. 선택 UI는 실제 도구를 실행하는 버튼이 아니라 후보를 좁혀 보는 필터임을 밝힌다.
- 목적 버튼은 키보드로 조작하고 선택 상태를 알 수 있어야 한다. 전체 후보로 돌아가는 선택을 제공하고 결과가 없는 경우도 안내한다. 후보 목록, 비교표·기능 매트릭스·가격/조건 상세가 같은 선택에 맞춰 함께 갱신되는지, 후보를 누르면 접힌 상세가 열리는지 확인한다. 숨겨진 다른 위치만 바뀌고 현재 화면에 결과가 없는 필터로 만들지 않는다.
- ‘무료보다 제작 경로’에서는 입력 준비 → 생성 → 사람 수정 → 엔진 가져오기 → 실제 플레이 검증을 HTML 또는 SVG의 읽을 수 있는 단계별 다이어그램으로 구성한다. 단순 화살표로만 이어 쓴 문장에 그치지 않고 각 단계에서 확인할 항목과 2D·3D·음향의 차이를 설명한다. 필요하면 image_gen으로 한글 요약 그림을 더하고 같은 내용을 대체 텍스트 또는 인접한 HTML로 제공한다. 생성 그림을 실제 제품 화면이나 실측 결과로 제시하지 않는다.
- ‘후보 비교 → 조건 확인 → 작은 실험’도 선택 절차를 설명하는 다이어그램임을 밝히고, 클릭할 수 없는 요소를 동작 버튼처럼 꾸미지 않는다. 도구의 기능·가격·권리·엔진 경로는 그 호의 공식 자료와 확인일을 기준으로 다시 조사하며 기존 호의 수치나 설명을 검증 없이 복사하지 않는다.

## 비교와 시각 자료

- 같은 작업에 쓰는 도구를 기능 매트릭스와 입력 → 생성 → 수정 → 엔진 연결 → 확인 흐름으로 비교하고, 기존 출처 표를 함께 제공한다. 가격은 통화·결제 주기·무료 한도·단위·세금과 확인일을 표시한다. 비교 조건이 같은 수치에만 축과 단위가 있는 차트를 쓴다. 단위가 다른 크레딧이나 무료량을 합산하거나 순위를 만들지 않는다.
- 성능은 동일 조건의 신뢰할 수 있는 실측이 있을 때만 비교하고 방법·표본·출처·확인일을 표시한다. 실측이 없으면 미측정이라 밝히고 시험할 방법을 제시한다. 관심도나 공급자의 광고 수치를 독립 성능 점수로 바꾸지 않는다. 차트에는 텍스트 또는 표 대안을 둔다.
- 이해에 도움 되는 공식 제품 화면, 게임 화면, 직접 연결된 영상과 명확한 출처·확인일을 우선한다. 공식 데모·직접 재현·이미지 생성 결과를 구분하고 접근 제한·저작권·공개 가능 여부를 확인한다. 생성 이미지는 설명에 도움이 될 때만 사용하며 실제 제품 화면이나 검증 결과로 제시하지 않는다.
- 공용 자산을 수정하면 이미 발행된 모든 호에 영향이 있는지 확인한다. 호별 수치와 시각 자료는 해당 호의 데이터로 고정하고 발행 후 검수 해시가 바뀌면 실제 검수를 다시 수행한다.

## 미디어 크기 검수
TOP 10의 설명 그림은 본문 폭에 맞춰 원본 비율을 유지한다. 큰 고정 폭에 낮은 max-height를 조합해 그림이 작은 가운데 영역에 갇히게 하지 않는다. 공식 이미지 미리보기는 독립적인 16:9 틀에 contain으로 전체를 보여 주며, 복제한 이미지의 width/height 속성은 제거한다. 유튜브·트레일러도 같은 기준선과 비율을 맞춘다. 320·390·768·1440px에서 이미지 상자와 원본 비율, 미리보기 16:9, 가로 넘침을 실제로 검사한다. 이미지가 늘어나거나 잘려 보이면 콘텐츠 완료로 처리하지 않는다.
출처가 확인된 제작자 시연과 공식 트레일러는 대표 자료를 접힘 밖에 제공한다. 나머지 이미지는 상세에 보존하고 원문 링크로 접근하게 한다. 모든 절에 무관한 영상이나 장식 이미지를 채우지 말고 섹션별 자료 유무·노출 위치·미확인 범위를 기록한다.

## 아이디어를 그림과 함께 설명하기
게임 아이디어 세 개와 AI 중심 제작 제안 세 개에는 각각 핵심 행동·선택·결과가 드러나는 대표 개념 그림을 붙인다. 같은 예시를 이미 생성했다면 내용이 맞는지 확인한 뒤 재사용할 수 있다. 분위기 그림만으로 규칙 설명을 대신하지 않는다. 제목·단계 문구의 한글, 본문과의 일치, 대체 텍스트와 캡션을 확인하고, 미제작 제안이며 실제 게임 화면·테스트 결과가 아님을 표시한다. 해외 자료의 JSON과 화면 자산도 호별 날짜 파일에 보존해 다음 호 수정이 이전 호를 바꾸지 않게 한다.
